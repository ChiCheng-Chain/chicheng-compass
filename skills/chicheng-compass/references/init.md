# 初始化

普通初始化的完成标准：先完成 [本地忽略](local-ignore.md)，再在明确目标下补齐缺失的通用骨架，列出新增、保留和未完成项。已有内容及团队规则保持原样。

目标先按 [项目发现](project-discovery.md) 确认。当前是项目根或其内部时，在真实项目根建库；当前是多项目父目录时分别列出候选与既有知识，用户未指定目标前不创建父目录知识库、不批量初始化。没有工程标识但用户明确认定为项目的目录仍可作为目标。

## 选择本次范围

用户只要求初始化时，执行下面的骨架流程。用户明确要求扫描项目并建立知识时，可按需参考 [推荐的首次知识建设流程](knowledge-building.md)，也可以采用用户选择的方法。已有骨架可以复用；这不新增第五个动作，不要求每次初始化都扫描或调研。

用户明确要求按新版流程重新建设已有知识时，沿该指南补齐业务理解、模块依赖和代码导航缺口，复用已有内容并先提案，不清空重建。仅重复调用普通 `init` 不会改写已有知识。

1. 确认目标项目目录确实存在。采用用户明确的位置；多个仓库或 worktree 并存时，指出本次目标。非 Git 目录也能初始化，不需要 CodeGraph。
2. 读取目标范围内适用的仓库规则，检查默认资料目录及已有内容。目录占用、链接指向其他位置等情况先说明，不能通过覆盖或迁移解决。
3. 选择以下一种方式创建缺失文件。
4. 报告新增和保留内容，说明本次骨架操作没有填充项目知识；已有知识仍保留。可告知推荐知识建设流程，用户尚未选择时不继续扫描。

## 可选脚本

有 Python 3.10+ 时，可执行 Skill 内的脚本，所有路径先替换为本次实际绝对路径，不从下例猜项目位置：

```text
python -X utf8 "<Skill绝对路径>/scripts/init_workspace.py" --project "<项目绝对路径>"
```

脚本先检查所有目标并准备本地忽略，再从 [初始骨架](../assets/scaffold/README.md) 复制五个文件到 `docs/ChiChengDocs/`，其中包括项目专属信息的说明入口。使用独占创建保留现有文件；不会填充项目知识或安装工具。输出包含 `local_ignore`、`created`、`preserved` 和目标根目录。

如果路径冲突或越过目标目录，脚本报错并说明问题。未经用户选择，不改用其他目录重试。
