# 全局调用：项目发现与知识引用

Skill 可以只安装在个人目录，项目中只保存各自的知识，不需要项目级 Skill 或客户端配置。安装位置用于读取 Skill 资源；当前工作目录或用户指定位置才是项目发现起点。不会扫描整台电脑，也不从全局 Skill 目录推断业务项目。

## 调用后先定位

用户显式选择 Skill 但未给动作时，先执行本页的只读发现和简短介绍，再给出四动作的选择；这不是自动建库或新增第五个动作。用户已指定动作时，用同一发现结果定位目标，再进入所选动作。

- **当前项目**：起点位于 Git 仓库内时采用最近 Git 根，包含 .git 为文件的 worktree。不要把 backend 等子包另建知识库。非 Git 项目可以通过最近祖先的工程标识或既有 Compass 入口识别；用户明确指定的实际项目优先。
- **多项目父目录**：当前不属于明确项目时，向下轻量发现候选，不把父目录当成项目、不在父目录创建合并知识库。遇到一个项目根即停止展开其内部；独立嵌套仓库只有用户指定时另处理。
- **只有一个子项目**：可用唯一候选继续所选动作，并说明实际目标在子目录，不把产出写到父目录。扫描不完整时不将“目前只找到一个”当作唯一项目的确证。
- **多个项目**：逐项介绍与引用。用户没有指定写入目标时，init/sync 先请其选择，不随机挑项目或给所有项目建库；已有名称、路径或明确任务证据可用于消除歧义。
- **尚未找到**：说明范围和限制。用户明确认定当前目录就是非 Git 项目时可在该目录初始化；否则先问，不凭有 docs 或 scripts 就认定一个项目。

纯发现和目录介绍保持只读，不调用本地忽略准备、不创建记录、不修改知识时间。实际选择项目并进入 init/read/sync 前，才按 [本地忽略](local-ignore.md) 准备该项目，再处理它的规则和知识。独立 Skill 演进仍以用户指定副本为准，不为发现项目而改变 evolve 目标。

## 如何介绍和引用

每个项目分别列出：名称、实际项目路径、已有知识入口或“未找到默认入口”、一两句用途、适合从哪里继续读。优先从该项目已批准知识的概述提炼介绍；没有时只读根 README 的简短用途，不根据目录名猜业务。只有骨架时明确“尚未建立”，发现入口不等于验证内容有效。

介绍可采用“项目｜用途｜知识入口｜适用任务”的简表，链接指向各项目原文件。关联是运行时的引用和阅读导航，不复制知识正文、不统一审批记录、不推断项目间存在依赖。进入一个项目后只加载它的约束和任务知识；跨项目任务分别说明来源和版本，互不继承规则。

默认只在回复中展示关联，不新增父目录索引或全局项目数据库。用户另行要求保存总导航时才保存链接型索引，不能用索引目录替代项目根；父目录已有聚合导航也不构成在此合并建库的授权。用户给出其他知识位置时沿用它，不把“默认入口未找到”说成“该项目没有文档”。

## 可选只读脚本

Python 3.10+ 可执行：

```text
python -X utf8 "<Skill绝对路径>/scripts/discover_projects.py" --directory "<本次工作目录>"
```

脚本仅返回候选与路径，Git标记/工程标识是发现证据，不保证目录就是用户要维护的业务。它不解析业务源码或生成用途摘要；Agent 再少量读取对应入口来介绍。

默认向下3层、最多检查2000个目录，跳过隐藏目录、依赖/生成目录、备份、docs/tests/fixtures及链接/Windows目录联接。限制、跳过范围和访问错误需如实说明；已明确的跳过目录可作为新的显式起点，不能自动无限扩大范围。没有 Python 时用文件工具按同一边界检查目录和默认入口即可。

如果目录只是聚合导航，或仓库内含多个独立知识目标，自动识别不足以确认时明确指出，由用户指定真实项目边界。项目归属不能仅由一个 package.json 或 README 推断为已经核验。
