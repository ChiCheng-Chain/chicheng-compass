# 第一步：本地忽略

用户显式使用 Compass 处理项目时，先按 [项目发现](project-discovery.md) 明确实际项目，再设置并验证该项目 `docs/ChiChengDocs/` 的 Git 本地排除。仅发现和介绍多个项目不修改它们的Git元数据；安装 Skill 或普通开发对话不会触发此步骤，也不注册 Hook。

只修改 Git 返回的 `info/exclude` 文件，保留已有规则，不改共享 `.gitignore`、团队规则、索引或全局配置。不排除 Skill 源码及其他项目文件。这个准备步骤不需要另外提出知识更新提案；重复调用检查并复用已有规则。

## 推荐执行方式

有 Python 3.10+ 时，替换为本次明确的绝对路径：

```text
python -X utf8 "<Skill绝对路径>/scripts/init_workspace.py" --project "<项目绝对路径>" --prepare-only
```

它只准备忽略，不创建资料目录。普通 `init` 的完整脚本也内置此步骤，在写骨架前执行。

完成标准是：确认资料区没有已跟踪或暂存内容，规则有效，且没有改共享规则。脚本返回 `configured` 或 `already_configured` 后继续所选动作；返回 `not_git` 时说明当前不是 Git 工作区，无须排除，不自动创建 Git 仓库。

已跟踪或暂存的文件不会因添加规则而停止跟踪；遇到这种情况暂停并请用户决定，不擅自取消跟踪。规则覆盖、Git 不可用或其他错误导致无法验证时，同样说明问题及已完成的操作，不宣称资料已仅留本地。

## 没有 Python

使用文件工具配合 Git 完成等效操作：

1. 在明确项目下用 `git -C "<项目>" rev-parse --show-toplevel` 定位仓库根。确认非 Git 目录时跳过；其他错误先报告。
2. 计算该项目 `docs/ChiChengDocs/` 相对仓库根的路径，用 `git ls-files -z -- ":(literal)<相对路径>"` 检查跟踪及暂存内容；有结果就暂停。
3. 在仓库根用 `git rev-parse --git-path info/exclude` 定位真实文件。返回相对路径时以仓库根解析；不要假设 `.git` 一定是目录。
4. 保留文件原有内容，仅追加尚不存在的根锚定规则。项目就是仓库根时为 `/docs/ChiChengDocs/`；子项目需带上其相对前缀，路径中的 Git 匹配字符需要转义。
5. 在仓库根运行 `git check-ignore --no-index -q -- "<相对路径>/"`，退出码为 0 才算验证成功。验证失败就报告，不改共享规则。

## 作用范围

本地排除不随提交传播，其他人的克隆不会获得此设置；同一仓库的 linked worktree 可能共享该排除文件。重新克隆后再次显式使用时重新准备即可。

忽略只是避免普通 `git add` 收录未跟踪资料，不是权限控制或保密措施；强制添加仍可绕过，也不会清除历史提交。

用户指定默认目录之外的文档或记录位置时，说明它不受此规则保护，由用户决定是否额外忽略，不扩大默认规则。`evolve` 仅针对独立 Skill 副本且未指定项目时不执行项目排除；Skill 副本内的演进记录也不在默认资料区规则内。
