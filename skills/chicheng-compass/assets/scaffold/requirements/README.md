# 需求资料入口

每项需求独立建目录，目录命名和最低需求文档要求见 [个人约束](../constraints.md)。例如 `2026年10月21日-执行报告文件生成/`，其中可使用 `需求文档.md` 说明需求，其余调研、讨论、确认稿、设计、原型和附件按需补充。

需求涉及多个版本时，可以在其入口写清当前进展、有效文档和阅读顺序。特别区分“已讨论”“需求已确认”“设计中”“已实现”，避免把计划当作项目现状。

原有需求资料可以先链接，迁移前由使用者决定。需求落地后，只把值得长期复用的概念、约束和决策提炼到项目知识；详细过程仍保留在需求资料中。

本文件提供组织建议；目录和文档的最低要求以个人约束为准，需求流程及文档具体写法自由调整。
