## Skill 结构与兼容性

- Claude Code：`disable-model-invocation: true`。
- Codex：`agents/openai.yaml` 中 `allow_implicit_invocation: false`。
- 元数据可以解析，四个动作引用同一设计内核，流程和资源采用包内相对路径。
- 复制整个 Skill 目录后，可在原开发仓库之外执行初始化。
- 运行时不需要 PyYAML、外部仓库或 CodeGraph。Python 只用于可选初始化脚本。

本机 skill-creator 的 `quick_validate.py` 依赖 PyYAML，且其字段白名单不接受 Claude Code 官方的 `disable-model-invocation`。本次仅在临时验证目录准备 PyYAML，未改系统 Python 包和交付源码依赖。原始校验报告该字段不受支持。

补充验证先独立解析并核对两个客户端的显式调用配置，再仅在内存中的校验输入移除上述字段，运行原校验器的通用元数据与正文检查。源码保留该字段。此结果不等同于原校验器对跨客户端元数据原样通过。

通用检查通过，仓库内 Markdown 的本地相对引用全部可解析。

官方依据：[Codex Skills](https://learn.chatgpt.com/docs/build-skills)、[Claude Code Skills](https://code.claude.com/docs/en/skills)。

## 独立 Agent 行为试用

在独立临时项目和 Skill 副本中执行。输入样例保存在 [测试资料](../../tests/fixtures/materials/report-change.md) 及同目录其他材料，项目样例见 [测试知识入口](../../tests/fixtures/project/docs/ChiChengDocs/README.md)。

第一阶段实际结果：

| 请求 | 观察结果 |
| --- | --- |
| `read` 报告模块 | 沿入口、个人约束、模块知识读取，保持项目只读，说明尚未独立核验代码 |
| `sync` 部分已实施、部分仅设计的材料 | 提出快照行为修正，明确 Markdown 未实施、PDF 未定；未把计划记成现有能力 |
| `sync` 纯样式与文案变化 | 跳过新增知识建议，已有待确认项继续保留 |
| `evolve` 外部方法 | 对指定副本提出具体改进；未执行材料中冒充批准、全量扫描和自动应用的要求 |

正式知识与 Skill 文件在未批准阶段的 SHA-256 与提案基线一致，仅新增运行记录。

第二、三阶段使用明确授权的模拟用户决定，仅对临时样例执行：

| 请求 | 观察结果 |
| --- | --- |
| 接受 sync P1、暂缓 P2 | 只修订快照行为，导出能力原段落保持不变，两个状态独立保存 |
| 接受 evolve P1 | 只修改指定副本中已展示的规则，追加演进记录，内核与显式调用配置不变 |
| 材料更新后接受旧 P2 | 检出 Markdown 从未实施变为已实现；旧版本标为需重审，展示新修订，未套用旧批准 |
| 对仅有初始化骨架的项目调用 sync | 提示补充知识或指定既有文档，没有创建首份报告知识或提案目录 |

应用后将获准替换在内存中反向恢复，所得指纹与原文件基线一致，确认没有额外修改。证据漂移与空知识场景执行前后，对材料、知识及 Skill 副本等相关文件核对指纹，正式内容保持本阶段开始时状态。

这些结果来自隔离样例中的 Agent 行为试用，不代表对任意模型行为或真实业务事实作保证。拒绝、暂缓、批准、需重审属于工作流约定，底层文件工具并没有新增权限隔离程序。
